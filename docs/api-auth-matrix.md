# API Auth Matrix

State of every API route family **after the Phase 1 security pass** (June 2026).
Source of truth for "who can call what". Update this file whenever a route's
auth posture changes.

## How auth is layered

1. **Edge (Clerk middleware, `src/middleware.ts`)** — every route requires a
   Clerk session **except** the explicit public matcher:
   `/`, `/sign-in*`, `/sign-up*`, `/api/webhooks/clerk` (svix-verified),
   `/api/auth/check-username` (rate-limited; needed pre-session by the sign-up
   form), `/api/pwa-status`, `/api/cron/*` (CRON_SECRET-verified).
2. **Handler auth (`src/lib/auth.ts`)** — `getCurrentUser()` /
   `requireAuth()` / `requireAdminAuth()` (admin = `ADMIN_USER_IDS` env, Mongo
   user ids) / `isAdminUser()`.
3. **Ownership / scope** — `verifyCollectionAccess()` (`src/lib/collections.ts`;
   personal owner or group member/admin, handles legacy Clerk-id and ObjectId
   `ownerId` formats), `isGroupMemberOrAdmin()` (`src/lib/groups.ts`),
   participants checks on decisions (match both Clerk-id and ObjectId-string
   forms — personal decisions store Clerk ids, group decisions store ObjectId
   strings).
4. **Rate limiting (`src/lib/rate-limit.ts`)** — Mongo-backed fixed window
   (`rate_limits` collection, TTL index), fail-open, per-user or per-IP keys.
5. **Cron/webhook secrets** — `verifyCronAuth()` (`src/lib/cron-auth.ts`,
   timing-safe) for `/api/cron/*`; svix signature verification for
   `/api/webhooks/clerk` (fails closed in production if
   `CLERK_WEBHOOK_SECRET` is unset).

Conventions: foreign/missing resources return **404** (no existence leak);
membership/role failures return **403**; missing session returns **401** (or
the edge redirect).

## Required environment variables

- `ADMIN_USER_IDS` — comma-separated Mongo user ids with admin access.
- `CRON_SECRET` — must be set in Vercel so cron invocations carry
  `Authorization: Bearer …`; handlers return 500 if unset, 401 on mismatch.
- `CLERK_WEBHOOK_SECRET` — required in production (webhook fails closed).
- `ADMIN_ALERT_EMAILS` — alert recipients (replaces a hardcoded address).
- `INTERNAL_API_SECRET` — internal bypass for cost-monitoring collection.

## Known gaps / deferred

- **Unsubscribe links**: email templates embed `?token=` but nothing populates
  the token and the token branch returns 501 — no live email contains a
  working unsubscribe link, and `email/unsubscribe` is edge-gated so
  signed-out clicks redirect to sign-in. Proper fix is a signed-token link
  (planned with Phase 5 notification work).
- `admin/alerts` POST still _sends_ to a hardcoded personal address (send
  target, not a response leak).
- `auth/register` / `resend-verification` / `verify-email` have no callers
  (Clerk SDK owns the real flow) — candidates for deletion in a later pass.
- `verify-email`'s code-verification branch is dead code (documented in the
  route); Clerk's emailed link/sign-in flow is the real mechanism.
- Rate limiter is fail-open by design (availability over strictness).
